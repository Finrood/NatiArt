# Storefront image ownership

Cart, mini-cart, checkout summary, product cards and detail/related images use `ImageCollection`. Each view updates a collection of stable keys and source paths or local files. Signals publish loading/loaded/error/empty state and ordinary raw object URL strings. Removing/replacing a key cancels its subscription and revokes its URL immediately; owner destruction releases everything. Local File identity changes refresh an unchanged line key.

ProductService shares at most 32 pending path requests with ref-counted replay. It retains no completed bytes: completion, cancellation and errors evict the cached observable. Additional distinct pending paths are uncached. A successful product update/delete invalidates pending cache entries and refreshes live owners, including unchanged image paths. New owners refetch the same path after an earlier request completed. Requests continue using the configured image API and authorization interceptor; no public storage URL or access bypass is introduced.

Missing/failed images use a small inline SVG with accessible alt text. Decode errors release their URL and fall back once. Repeated emissions for the same source do not retry a failed image forever; a replacement, invalidation or new owner can retry. No view requests the nonexistent placeholder asset or leaves an absent image pulsing forever. Detail thumbnails retain server array order independently of response timing.

Verification: HTTP tests cover concurrent owners/repeated emissions, last-owner cancellation, same-key path/File replacement, unchanged-path product mutation invalidation, one-shot fallback and 100 browsing replacements with matching create/revoke counts. Real mini-cart plus summary components share a delayed GET and render through signals without an extra click; a removed delayed cart line cancels its request. Summary replacement/removal uses real rendered inputs. Full ChromeHeadless suite: 201 specs. Explicit production build is required.

When combining CA13/CA21, use the persisted custom-art reference through its authorized API rather than falling back to public product art; extend the source contract with an authorized resolver if required. Preserve CA26 server image ordering, CA34 keyboard controls, CA36 route/zoom recovery, and CA23 catalog pagination. Keep existing admin preview upload lifetimes independent; these collections own only storefront image URLs.
